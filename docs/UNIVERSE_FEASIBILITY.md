## 0. 结论先行

1. **退市标的日线：可用。** baostock 能一次取回完整证券主表
   （`query_stock_basic()` 无参数），其中 `type=1`（股票）5,566 只：
   在市 5,225、已退市 341。7/7 只抽样退市票都能取到日线，区间覆盖到
   `outDate` 当日**或前一日**（**以最后可得行为准**，见 §2.2）；
   前复权（`adjustflag=2`）在退市票上也可用，
   实测有真实复权因子并在价格上生效。**baostock 不覆盖北交所**
   （`bj.*` 返回 `error_code=10004011 股票代码未标识sh或sz`），也不含 B 股。
2. **历史时点成分：没有可直接下载的「某月成分快照」文件，但官方调样公告可重建。**
   中证官网只提供**当前**成分文件（`000300cons.xls`，实测日期 2026-11-11、
   300 行；`000905cons.xls` 500 行），历史文件名模式一律 404；
   官网 API 也没有按日期取成分的可用参数。另一方面，中证公告接口能枚举
   2018–2026（至 11-13）**1,461 条「指数调样」公告**，半年度调样附件 xlsx 含
   全指数「调入/调出」明细（2018-12 附件：沪深300 各 24 条、中证500 各 50 条），
   可解析。**方案可行，但要逐条重建并以当前快照为锚反向回放；不是现成文件。**
3. **全 A 池规模：约 5,900 只（含退市）。** baostock 覆盖沪深 5,566 只
   （在市 5,225 + 退市 341）；北交所另 355 只（`ak.stock_info_bj_name_code()`，
   2026-11-13），baostock 无覆盖。2018-01-01～2026-11-12 期间曾上市的
   沪深标的共 **5,471 只**（含期间退市 246 只）。
4. **成本：全 A 2018–2026 日线可行但偏重。** 沪深全池约
   **10.1M 行、1.14 GB CSV（约 170 MB parquet）**、**5,471 次请求**；
   单票 10 年请求实测 3.8–4.9 秒，**串行约 6 小时**（5.3–7.4 小时区间；
   独立验收实测均值 4.0 秒/请求 → 6.1 小时）。
   **禁止并发**：baostock 并发不安全，裸并发会在 2,000 行边界静默截断
   （`error_code=10001001`、末根日期倒退数月，见 §5.2 警告）。
   推荐离线一次性**串行**落盘 + 断点续跑，不在回测时联网。
5. **推荐方案：以「全 A + 退市」作为主池，历史成分重建作为可选的第二证据。**
   理由：后续研究是**横截面选股**，不是复制指数；全 A 池直接消除
   「用 2026 年成分回测 2018 年」的成员资格前视，且样本量远超 2,500 聚类门槛。
   「当前成分 + 退市样本 + 行业/市值分层」只能给偏差**上界**，不能当无偏池，
   只能作为敏感性检查，不能作为主结论。
6. **最大的残余风险不是数据取不到，而是「退市/并表退出收益」的口径。**
   baostock 只给价格序列，不给退市原因或公司行动。口径已在 §6 定为
   一条可执行规则 + 一张人工例外表：
   **默认 = 该票最后一个 `tradestatus==1` 交易日的收盘价**
   （已含退市整理期跌幅，实测 −62.9%～−93.7%）；
   **禁止默认记 −100%**（会双重计亏、系统性高估损失）；
   换股/并购类（如 `sh.600005` 换股平收 3.71）走人工例外表。
   退出时点也不可执行（最后可交易日距 `outDate` 1–49 天），
   回测按「最后可交易日结算 + 冻结期不调仓」处理。
   341 只的分类表仍是待办，但**价格口径本身已经可执行**，不再阻断建池。

## 2. 退市标的实测（Q1）

### 2.1 证券主表

`query_stock_basic()` **不传代码**时返回全量证券主表，这是本任务最省请求的入口：

```text

      "delisted", (st.outDate != "").sum())

type

1    7830

```

- `type=1` = 股票；`type=2` = 指数；`type=4` = 债券（样例：南化转债等）；
  `type=5` = 基金/ETF（样例：华夏上证50ETF 等）。

关键字段（与 §6.6 一致）：

```text

```

- **「退市日行」不是普适形态 —— 一律以最后可得行为准。**
  本报告 7 只老退市票的最后一根是 `outDate` 当日、`tradestatus=0`、
  `volume`/`amount` 为空但 `close` 有值；但 2025–2026 年新退市票的日线
  **止于 `outDate` 前一日**，根本没有 `outDate` 当日的行。独立验收实测
  （issue #82）：

  ```text
  sz.300379 东通退   outDate=2026-01-22  末根=2026-01-21  (13 行)
  sz.300391 长药退   outDate=2026-04-13  末根=2026-04-10  (63 行)
  sz.300630 普利退   outDate=2025-05-22  末根=2025-05-21  (90 行)
  sz.301139 元道退   outDate=2026-10-28  末根=2026-10-27  (195 行)
  ```

  实现上不要用 `outDate` 去 `loc` 最后一行，也不要假设 `outDate` 当日必有一根；
  取该票日线序列的**最后一根**作为退市边界即可。若最后一根
  `tradestatus=0`（老票形态），视为**不可成交**，退出价取最后一个
  `tradestatus==1` 的收盘（§6）。
- `outDate` 之后查日线返回 0 行（`sh.600005` 查 2018 年：0 行），
  `ipoDate` 之前也返回 0 行；没有报错，是空结果。
- 7/7 抽样成功，**但未全量验证 341 只**；不能把抽样率写成 100% 覆盖。

### 2.3 复权可用性（修正 SKILL §6.6 的一条警告）

SKILL §6.6 写「已退市标的的除权除息，三个源全缺……做复权必然对不上」。
本次实测**不支持把它当成普遍结论**：

```text
sz.000024 招商地产: raw 488  qfq 488  identical 0/488
  raw 2014-01-02 20.5400 -> 2015-12-30 40.5000
  qfq 2014-01-02 13.1825 -> 2015-12-30 40.5000
sh.600005 武钢股份: raw 1,726 qfq 1,726 identical 0/1,726
  raw 2010-01-04 8.1800 -> 2017-02-14 3.7100
  qfq 2010-01-04 7.1325 -> 2017-02-14 3.7100
sh.600087 退市长油: raw 827 qfq 827 identical 0/827
  raw 2011 4.9400 -> 2014-06-05 0.8300
  qfq 2011 2.7375 -> 2014-06-05 0.8300
sz.000939 凯迪退: raw 964 qfq 964 identical 0/964
  raw 2017 12.8400 -> 2020-12-17 0.1500
  qfq 2017 6.4200 -> 2020-12-17 0.1500
sz.000024 的 adjust_factor 返回 2 条:
  ['2014-06-06', '0.989987', '6.418465', '6.418465']
  ['2015-05-22', '1.000000', '6.483380', '6.483380']
EXIT=0
```

结论：**至少这 4 只退市票的 qfq 是真实生效的**，因子可单独查到。
短窗口样本看起来 qfq=raw，是因为窗口内没有除权除息，不是因子缺失。
落地时必须逐票校验（`query_adjust_factor` 是否有记录、qfq/raw 比率是否随
除权日变化），不能假设「退市票一定不能复权」，也不能假设「一定可以」。

### 2.4 失败模式

| 现象 | 实测 | 处理 |
|---|---|---|
| 北交所代码 | `query_stock_basic` 返回 0 行；日线 `error_code=10004011` | 用新浪/北交所官方补；或明确剔除北交所并写进预注册 |
| **并发截断（严重）** | 多进程并发取数在**正好 2,000 行**处断流，`error_code=10001001`，末根日期错到 2026-04-02（真值 2026-11-12）；4 并发多轮中招、8 并发 6/8、2 并发 1/6；串行对照恒完整 | **禁止并发**；串行 + 逐请求校验 `error_code` + 末根日期校验 + 断点续跑（§5.2） |
| 退市日行非普适 | 老票有 `outDate` 当日 `tradestatus=0` 行；2025–2026 新票止于前一日 | **以最后可得行为准**；退出价取最后 `tradestatus==1` 收盘（§2.2、§6） |
| `rs.next()` 偶发重复页/挂起 | 一次 1 年 600519 查询回放了 200 万+ 行（CPU 100%）；重跑同参数正常 243 行 | 必须设行数上限 + 日期唯一性校验 + 进程级超时；不能裸 `while rs.next()` |
| 请求无超时参数 | baostock 不暴露 socket timeout | 外层 `timeout`/子进程隔离，失败重试 |
| 慢查询 | 单票 10 年 2,637 行耗时 3.76–4.88 秒 | 见 §6；离线批量，回测不联网 |

> 重复页/挂起无法稳定复现，属于**源侧/客户端偶发缺陷**；把它当作运营风险，
> 不把它当作“数据缺失”。
>
> 并发截断则**稳定可复现**（见 §5.2）：它不是「偶发」，而是并发下的确定失效形态。
> 因此把「串行」写进预注册作为硬约束，不做「加重试后再并发」的折中。

### 3.4 重建成本与风险

| 项 | 实测/估算 | 说明 |
|---|---|---|
| 公告列表 | 1,461 条，9 次 POST，6.3 秒 | 实测 |

| 附件大小 | 抽样 20 个 xlsx 共 1.34 MB，平均 66.8 KB | 实测 |
| 附件数量 | 2018 年内成功处理的 88 条明细中 26 条带 xlsx 链接 | **样本偏 2018，不能外推到全期**；后续被 WAF 中断，未测全量 |
| 工程复杂度 | 解析生效日、正反向回放、缺失公告校验、300/500 计数校验 | 约 1–2 人日；比取日线更易出错 |

**关键判断**：历史成分重建**不是「下载一个月文件」**，而是
「枚举 1,461 条公告 + 逐条下载附件 + 反向回放」，仅详情抓取就 **≥4 小时**
（每 ~84 条撞一次 WAF、每轮冷却 ≥15 分钟）。它可行，但成本明显高于
「全 A + 退市（串行约 6 小时、一次落盘可复用）」；只有在研究问题必须
复刻指数成员资格时才值得做。

### 5.1 实测基准

```text
600519 2016-01-01..2026-11-12:
  raw err=0 rows=2637 t=4.88s

- 1 年请求 0.73 秒；10 年请求 3.8–4.9 秒（数据量与解析时间都在涨）。

### 5.2 2018–2026 全池估算

| 项 | 值 | 算法 |
|---|---:|---|
| 标的数（沪深，曾上市） | 5,471 | 主表 as-of 推导 |
| 总行数（近似交易日） | ≈10.07M | 逐票 `max(ipo,2018-01-01)` 到 `min(out,now)` 的工作日 × 0.965 |
| CSV 体积 | ≈1.14 GB | 10.07M × 113 B |
| parquet 体积 | ≈170 MB | 按 CSV 的 ~15% 粗估（未实测压缩率） |
| 请求数 | 5,471 | 1 票 1 次全区间 |
| 串行时间 @3.5 秒 | 5.3 小时 | 5,471 × 3.5 / 3600 |
| 串行时间 @4.0 秒 | 6.1 小时 | 独立验收实测均值 4.00 秒/请求 |
| 串行时间 @4.9 秒 | 7.4 小时 | 5,471 × 4.9 / 3600 |
| **计划口径：串行** | **约 6 小时** | 取 5.3–7.4h 的中值；断点续跑，中断可续 |
| ~~4 并发~~ / ~~8 并发~~ | **不可用（作废）** | 线性加速是真的，但会静默截断样本，见下方警告 |

> **⚠️ 禁止并发：baostock 会静默截断，产出残缺样本。**
>
> 4 并发**不是**「快 3 倍的等价方案」，而是**失败方案**。2026-11-13 独立验收
> （V27 / issue #82）用 4 个独立进程各持一个 baostock 会话并发取同一批量，
> 串行对照组恒为完整的 2,149 行：
>
> ```text
> == serial 对照 ==      sh.600519 rows=2149 md5=9bc8d3579c3b last=2026-11-12
> == 4 并发 round 1 ==   sh.600519 err=10001001 rows=2000 md5=b5a1b8a0f0f9 last=2026-04-02
>                        sz.000001 err=0 rows=2149；sh.601318 err=0 rows=2149；sz.300750 err=0 rows=2044
> == 4 并发 round 2 ==   同上，sh.600519 仍 err=10001001 rows=2000
> == 4 并发 round 3 ==   sh.600519 与 sh.601318 双双 err=10001001 rows=2000
> == 8 并发（压测） ==   6/8 会话 err=10001001 rows=2000
> == 2 并发（3 轮） ==   1/6 会话 err=10001001 rows=2000
> == 串行 4 票 ==        4/4 完整 2149/2149/2149/2044，wall=28.0s
> ```
>
> 失效形态固定为**正好 2,000 行截断 + `error_code=10001001`**（baostock 分页
> 在第一页边界断流），且最后一根日期错到 **2026-04-02**（真值 2026-11-12）——
> 少了 149 行 ≈ 7 个月。对 `while rs.next()` 而不检查 `error_code` 的写法，
> 这是**静默数据缺失**：回测照跑，样本少一截，且截断票在末尾看起来"正常收盘"。
> 2 并发也会中招（1/6），所以不是「少开点线程就行」。
>
> **结论：建池一律串行，约 6 小时；禁止任何形式的跨进程/跨线程并发取数。
> 提速只能靠断点续跑（从已完成票继续），不能靠并发。**

> 若要包含北交所，另加 355 只；baostock 取不了，需新浪逐票补
> （单次只有 1,023 根，10 年需分段/换源），成本另计。

### 5.3 分批 + 退避的可行性

- **可行，但只能串行**：5,471 次请求、1.14 GB，**串行约 6 小时**落盘，
  属于一次性成本。并发看起来更快，但会静默缺数据（§5.2），**不可用**。
- **必须做的保护**：
  1. 每票行数上限（例如 3,500）与「日期唯一」断言，防止 §2.4 的重复页；
  2. **每次请求后校验 `error_code == "0"`**；非 0（尤其 `10001001`）整票作废重取。
     不能"有行就算成功"——截断样本也有 2,000 行；
  3. **末根日期校验**：与主表 `outDate` / 全局最后交易日比对，偏差超过
     5 个交易日即判截断并重取（截断特征就是末根日期倒退数月）；
  4. 进程级超时（单票 60 秒）与重试（3 次，指数退避）；
  5. **断点续跑**：以 `code` 为单位落 parquet，记录行数 + 首末日期；
     重跑时只补缺失/校验失败的票——这是串行模式下唯一的提速手段；
  6. 不在回测时联网；全部走本地缓存。
- **不建议**：回测时逐日/逐票实时取数；也不建议在 `source/` 主路径 import baostock
  （沿用 `requirements-research.txt` 的隔离约定）。

## 6. 替代方案对比与推荐（Q5）

| 方案 | 消除成员资格前视 | 消除退市幸存偏差 | 数据/工程量 | 样本量 | 结论 |
|---|---|---|---|---|---|
| A. 重建历史沪深300/中证500成分 | 是 | 是（含退市调出） | 1,461 条公告 + 附件 + 反向回放；1–2 人日；WAF 限速 | 300/500/期 | **可行但重，非首选** |
| B. 全 A + 退市（as-of 过滤） | 是 | 是（退出收益口径见下） | 5,471 请求、10.1M 行、1.14 GB、**串行约 6 小时**（禁止并发） | 5,471 只 | **推荐主池** |
| C. 当前成分 + 退市样本 + 行业/市值分层 | **否**（仍是 2026 成分） | 部分（只补样本） | 最小 | 300 + 若干退市 | **只能做偏差上界/敏感性，不能当主结论** |

### 推荐：B 为主，A 为可选第二证据

理由：

1. 后续研究是**横截面选股**，不是复制沪深300。用当前成分回测的本质错误是
   「用 2026 年知道会活下来/会入选的票去回测 2018 年」；全 A 池把选择集还原为
   「当时已上市且可交易的所有票」，直接消除这类前视。
2. 全 A 池 5,471 只，远超 §3.6.6 的 2,500 聚类门槛（5,471 × 8 年 × 4 季度
   ≈ 17.5 万个槽位）；即使每期随机抽 300 只，8 年也有 9,600 个「票 × 季度」
   槽位。**样本量不再是瓶颈**。
3. 成本可接受：一次性**串行约 6 小时** + 1.14 GB；比重建 1,461 条公告的
   工程风险低，且日线一次落盘后可离线复用。
4. A 方案只有在需要「复刻指数成员资格」或做「指数增强 vs 全市场」对照时才需要；
   它不能替代 B，因为指数成员本身也只是一小部分股票。

### 推荐落地的池子定义（写进下一轮预注册）

```
主池：2018-01-01 起，每个决策日 d：
  - ipoDate + 120 个交易日 <= d（次新股回避）
  - d 在 [ipoDate, 最后可得行日期] 内；边界以该票日线最后一根为准
    （不假设 outDate 当日有行），outDate 后不再计入
  - tradestatus == 1（停牌日不产生买点）
  - 非 ST（isST == 0；或单独分层统计）
  - 剔除北交所（baostock 无数据），或另用新浪补并单独报告
  - 流动性：d 前 20 日均成交额 >= 阈值（阈值预注册，例如 2,000 万元）
```

**退市/退出收益口径：一条默认规则 + 一张例外表**（预注册写死，不再"三选一"）。

**规则 1（默认，可直接执行，覆盖大多数退市票）**：
退出价 = 该票**最后一个 `tradestatus==1` 交易日的收盘价（qfq）**。
不是 `outDate` 当日价，更不是 −100%。

- 这个价格**已经包含退市整理期的跌幅**，无需外部原因表即可结算。独立验收
  实测最后 30 个可交易日跌幅：

  ```text
  sz.002450 康得退  3.17 → 0.20   -93.7%
  sz.000939 凯迪退  0.95 → 0.15   -84.2%
  sz.301139 元道退                -80.0%
  sz.300391 长药退                -78.7%
  sz.300630 普利退                -62.9%
  ```

- **禁止默认记 −100%**：那是在已实现 −62.9%～−93.7% 的亏损上**再记一次
  全额亏损（双重计亏）**，会系统性高估损失。`−100%` 只能作为「破产清算、
  实际回收为 0」的少数票的**显式分类结果**，不能当默认值，也不能替代分类。

**规则 2（例外表：换股/吸收合并，必须人工/半自动分类）**：
这类退市的价格序列不反映真实退出价值，规则 1 会系统性**低估**（价格平收，
但持股人实际拿到了承接方股票或现金）。

| 代码 | 名称 | `outDate` | 形态 | 处理 |
|---|---|---|---|---|
| `sh.600005` | 武钢股份 | 2017-02-14 | 宝钢换股吸收合并；价格**平收 3.71**、无崩塌 | 按换股比例折算承接方（宝钢）股票，或按公告现金选择权；**不能**把 3.71 当真实退出价 |
| 其余 340 只 | — | — | **未逐只核** | 先按规则 1 过；命中下方判据的进人工复核队列 |

- **半自动筛选判据**：末段 30 个可交易日跌幅 **< 10%** 的退市票，高度疑似
  换股/并购（而非破产退市），优先人工核。这一步能把 341 只缩到人工可处理规模。
- 分类结果必须落表（代码 → 破产/造假/换股/其他 + 退出价来源），随预注册冻结。

**规则 3（退出时点不可执行，回测必须显式处理）**：
最后一个 `tradestatus==1` 交易日**不等于** `outDate`，中间隔着停牌：

- 独立验收实测：`sz.000939` 1 天、`sz.002450` 3 天、`sh.600005` **22 天**、
  `sz.000003` **49 天**（区间 1–49 天）。
- 「按退市日卖出」在实盘不可执行——等于「停牌数周后按停牌前价格结算」。
- 回测约定：退出价按规则 1 结算，但**退出记在最后一个可交易日**；
  从最后可交易日到 `outDate` 之间，持仓**不可调仓、不计次日收益**；
  这段「冻结期」长度单独报告（停牌长度本身就是负面信号）。
- 不允许用 `outDate` 之后的数据，也不允许把 `outDate` 当成交日。

> baostock 不提供退市原因，也不提供公司行动。规则 1 已让**价格口径可执行**；
> 剩余待办只有例外表的人工分类（规则 2）。这是下一轮开始前的前置项，
> 但不再是「无法下结论」的缺口。

### 如果全 A 不可行：最小可行替代

1. **只做偏差量级校验**：按决策日从主表做**分层随机抽样**（行业 × 市值 × 是否退市）
   抽 300 只/期，只取被抽中的票的日线。请求数从 5,471 降到约
   300 × 8 = 2,400 票-年（若每期重抽，需按票并集去重）；只能回答
   「偏差有多大」「随机池收益分布」，不能跑全市场排序策略。
2. **当前成分 + 退市补齐**：保留 300 只当前成分，另加 341 只退市中在
   2018–2026 曾上市的 246 只，按行业/市值分层加权；结果必须标注
   `biased-universe`，只用于敏感性，不用于宣称绝对收益。
3. **不推荐**：只把 14.4pp 当“已修正”——它同时包含成员资格前视、
   等权 vs 市值权重、价格指数不含分红三个来源；全 A 池只消除第一个，
   后两个仍要用总收益基准/权重口径处理（见 §7）。

## 7. 残余偏差与风险

1. **退市/并表退出收益（最大风险）**：见 §6。默认口径已定为「最后一个
   `tradestatus==1` 收盘价」，**禁止 −100% 当默认**（双重计亏）。
   残余风险只剩换股/并购例外表（需人工分类）与退出时点
   （最后可交易日距 `outDate` 1–49 天，实盘不可执行）。
2. **北交所缺失**：355 只在市（约占当前 A 股 6%），baostock 完全不覆盖；
   新浪可补当前/近 4 年，历史退市北交所无源。建议主池先剔除北交所并声明，
   或单独做北交所附录。
3. **B 股缺失**：baostock 主表 0 条；若研究只做 A 股，可接受；若要全市场，
   需另找源。
4. **ST/停牌/流动性**：全 A 含大量不可交易样本；必须 as-of 过滤，
   否则会引入「买了不能卖」的假收益。
5. **14.4pp 不是纯幸存者偏差**：R6 的等权买入持有 +14.26% vs 价格指数 −0.13%，
   还包含等权 vs 市值权重、价格指数不含分红。全 A + 退市只修正成员资格前视；
   比较绝对收益时要用**总收益基准**或同口径等权组合。
6. **qfq 逐票校验**：退市票的因子并非全部缺失，也并非全部可用；
   必须查 `query_adjust_factor` 并对比 raw/qfq。
7. **baostock 客户端缺陷**：并发会在 2,000 行边界静默截断
   （`error_code=10001001`，§5.2），**建池禁止并发**；串行下也有重复页/挂起
   （§2.4）。必须串行 + 行数上限 + 日期唯一 + 末根日期校验 + 超时。
8. **中证 API WAF**：详情接口**第 84 条即 403**，封禁 **≥15 分钟**
   （实测 7/15 分钟后重试仍 403），全量 1,461 条约 **≥4 小时**；
   附件域名 `oss-ch` 不受影响。重建必须限速 + 长冷却；不要多线程猛拉。
9. **公告重建的完整性**：漏一条临时调整就会把已退市票留在名单里，
   恰好重新引入幸存者偏差；必须用 300/500 计数与调样公告正文的
   “更换 N 只”做交叉校验。
10. **数据日期**：当前成分文件日期 2026-11-11；样本信息最新交易日 2026-10-30。
    两者不同源、不同日，不能混用。

## 8. 对后续选股研究的建议

### 8.1 是否值得做

**值得，而且是前置条件。** R6 已证明当前成分池的绝对收益不可信
（14.4pp/年）；在这个池子上继续调因子，只会把「选到 2026 年赢家」误当成 alpha。
全 A + 退市是成本最低、最直接消除该偏差的方案。

### 8.2 需要多少数据

| 用途 | 数据量 | 请求 | 时间/存储 |
|---|---|---:|---|
| 主池（沪深全 A + 退市，2018–2026） | ≈10.07M 行 | 5,471 | 1.14 GB CSV / ~170 MB parquet；**串行约 6 小时**（5.3–7.4h），**禁止并发**，断点续跑 |
| 北交所补丁（可选） | 355 只 × ≤4 年 | 355（新浪） | 约 37 MB，2 分钟 |
| 历史成分重建（可选） | 1,461 条公告 + 附件 | ~1,500–2,000 | **≥4 小时**抓取（限速 + ≥15 分钟/轮冷却）+ 1–2 人日工程 |
| 退市原因分类 | 341 只 → 半自动筛出换股候选 | 外部公告 | 半自动筛选把候选缩到人工可处理规模；**价格口径已可执行（§6）** |

### 8.3 排期建议

1. **先做 B**：主表 → 全 A 日线**串行**落盘（约 6 小时；每票校验
   `error_code`/行数/末根日期，断点续跑）→ as-of 过滤 → 用「随机 300 只/期」
   做一次偏差量级复算（对比 R6 的 14.4pp），确认池子行为符合预期。
   **不要为了赶时间并发取数**（§5.2）。
2. **同时定退市收益口径**：默认规则（最后 `tradestatus==1` 收盘）已定，
   只需跑半自动筛选（末段 30 日跌幅 < 10% → 换股候选）并人工核例外表；
   破产/造假票的 −100% 只用于显式分类，不做默认敏感性。
3. **再做选股研究**：在无偏池上重跑 R6 的 13 个候选或新预注册候选；
   样本量不再是问题，瓶颈回到持有期独立窗数与交易成本（R6 的结论不变）。
4. **A 方案按需**：只有在需要「指数增强」或「成员资格」类问题时才做；
   不要为了“看起来更严谨”而先做 1,461 条公告重建。

### 8.4 下一轮预注册必须写死的项

- 池子 as-of 过滤（上市天数、ST、停牌、流动性阈值、北交所去留）；
- **取数方式：串行 + 断点续跑，禁止并发**（§5.2）；
- 退市/并表退出收益：默认「最后 `tradestatus==1` 收盘」，禁止默认 −100%，
  换股/并购走例外表，退出记账在最后可交易日 + 冻结期不调仓（§6）；
- 基准：总收益指数（或同口径等权全 A），不是价格指数；
- 样本单位：票 × 季度聚类，≥2,500；
- 多重检验：候选数、试验次数、DSR/Bonferroni；
- 数据版本：主表拉取日、日线拉取日、当前成分文件日期。

## Goal

把本项目从"面向人眼阅读的回测研究工具"，重构为 **Hermes Agent 可直接消费的、带不确定性量化的交易决策引擎**：先修复使当前结论失效的正确性缺陷，让数字重新可信；再把"胜率主导 + 单点 argmax"的选择逻辑换成"风险调整后收益 + 多策略族共识 + 多重检验校正"，让建议可复现；最后固化一个稳定、自描述、无歧义的决策输出契约。股票侧与基金侧同步覆盖。目标持仓周期为日线波段（数天~数周）。

**已实测的现状证据（本契约所有阈值的依据，均在 600519 / 2020-01-02~2026-10-16 / 1643 根日线上测得）：**

- 最低 843 元 → 一手 8.4 万，`initial_capital=100000` 下**仅 66/1643 根 K 线（4%）买得起一手，且全部落在 2020-01-02~2020-04-13**；本金提到 100 万后交易数：唐奇安 1→29、MACD 1→32、均线趋势 1→42、Kelly 0→19、StochRSI 32→79。
- 581 组参数中 **197 组零交易、564 组不足 10 笔被判 -100、仅 17 组（2.9%）存活；40 个策略族中 36 个全灭**（含 README 当门面的"均线趋势"：84 组、44 组零交易、中位数 0 笔）。
- 评分中 **Wilson 胜率项占 |总分| 的 72.8%**；导致 年化12.65%/回撤34.96% 的组合排名低于 年化10.14%/回撤6.78% 的组合。
- **argmax 不可复现**：仅砍掉末尾 120 根 K 线（7%），最优策略即从 `StochRSI(14,25/75)` 翻为 `StochRSI(14,25/80)`，Top5 重合仅 1 个；存活 Top12 中 StochRSI 独占 7 席（58%），同源堆叠。
- 实际输出自相矛盾：StochRSI=100.00（极度超买）却报"今日信号：无（观望）"，并给出"明日买入触发：StochRSI 上穿 25（当前 100.00）"。
- 运行耗时 41s（jobs=1）/ 38s（jobs=4）；`pytest` 24/25 通过，1 项因缺缓存 CSV 失败（网络依赖，无离线保护）。
- README 多处与代码不符：示例 `均线趋势(5-13-34)` 不在网格内；"3 折 walk-forward 防过拟合"实为固定策略在子窗口重跑，未逐折重新寻优；基金侧"均含双边申赎费""评分与股票侧一致（Wilson 下界）"在 `fund_strategy/runner.py` 路径均不成立（零费率、无 Wilson、无 IS/OOS 切分）。

**接口形态推断（因 Hermes 自行拉取仓库并自主运行）**：以 CLI `--json` 输出到 stdout 为主契约，schema 完整写入 README 以便 Agent 自主发现；底层由同一个可导入函数产出该 schema，CLI 仅作薄包装，杜绝文本与 JSON 两套逻辑漂移。

## Acceptance criteria

### A. 正确性：让数字重新可信

- [ ] **A1 资金/整手可负担性**：回测头寸规模与标的绝对股价解耦（自适应资金或归一化头寸）。对 600519，全样本"买得起一手"的 K 线占比达 **100%**；`唐奇安(20/10)`、`MACD(12-26-9)`、`均线趋势(5-20-60)` 的交易数分别达到 **29 / 32 / 42**（与 100 万本金基准一致）。
- [ ] **A2 无"信号充足却零成交"**：对全部 581 组，凡 buy 信号数 ≥ 20 者，成交笔数为 0 的组数必须为 **0**（当前为普遍现象）。
- [ ] **A3 失败必须变响**：引擎统计并暴露"因资金不足/涨跌停/停牌未能按信号成交"的事件计数。人为将 `initial_capital` 设为极小值运行时，文本输出出现显式告警，JSON 的 `diagnostics` 非空，且以非零退出码或显式 `untradeable` 状态标记——不得静默产出看似合理的报告。
- [ ] **A4 暴露时长**：输出含 `time_in_market`（持仓天数占比）；年化收益与最大回撤的时间基准在输出中明确声明。对 600519，修复后 `time_in_market` 不再趋近 0。
- [ ] **A5 信号 T+1 一致**：基金信号回测与股票引擎采用同一 T+1 规则，消除 `_fund_backtest_signals` 的当日收盘 look-ahead。回归测试：构造仅最后一根 K 线发信号的用例，断言不产生当日成交。
- [ ] **A6 基金单一成本模型**：基金侧只保留一个回测执行路径，且含双边申赎费；参数寻优不得在零费率模型上评估（`optimize_parameters` 必须走含费路径）。代码中不再存在零费率的基金成交分支。
- [ ] **A7 尊重调用方窗口**：基金侧不再无条件 `DateOffset(years=3)` 截断；传入 `--start 20200101` 时输出报告的实际数据区间起点与请求一致，或在 JSON 中显式声明所用窗口及原因。
- [ ] **A8 单一 regime 定义**：历史分市场胜率与"当前市场环境"共用同一个标注函数；`_calculate_metrics` 的分桶标签集合与当前环境判定输出的标签集合完全相同（消除 StrongBull/Crash 被折叠进"震荡"、两套规则并存的问题）。测试断言两者一致。
- [ ] **A9 对比表数据卫生**：`__买入持有基线__` 伪行移出策略对比表，基线作为独立字段输出。对比表所有行的 `交易次数` 可安全 `.astype(int)`（当前诊断脚本正因此崩溃）。
- [ ] **A10 涨跌停按板块区分**：不再硬编码 ±9.9%；主板 ±10%、创业板/科创板 ±20%、北交所 ±30%、ST ±5%。对 688981（科创板）使用 20%。测试覆盖至少 3 类板块。
- [ ] **A11 止损跳空**：止损不再按理想止损价成交，而以 `min(止损价, 当日开盘价)` 成交。测试：构造开盘价远低于止损价的 K 线，断言成交价等于开盘价。
- [ ] **A12 贝叶斯路径基准一致**：`--opt bayes` 的选优与最终报告指标必须基于同一资金/窗口基准（当前按 OOS 自适应资金选参、却用原始 10 万本金报指标）。
- [ ] **A13 修复影响留证**：仓库内产出一份 600519 修复前后对比（存活策略数、零交易组数、代表策略交易数、年化、最大回撤、`time_in_market`、argmax 稳定性），含实测数据与运行日期。

### B. 可靠性：从"胜率最大化 + 单点 argmax"到"风险调整 + 共识 + 多重检验校正"

- [ ] **B1 评分量纲一致、风险调整**：胜率项不再主导。敏感性断言：合成结果 A(年化12%/回撤35%) 与 B(年化10%/回撤7%)，B 的分数必须**显著高于** A；对 600519 实际 Top12 度量，胜率项对 |总分| 的贡献占比 **≤ 40%**（当前 72.8%）。
- [ ] **B2 波动率自适应止损止盈**：不再对所有策略固定 8%/15%，改为按 ATR/波动率缩放，且允许策略自身退出逻辑覆盖。测试：同一策略在高/低波动子样本上的止损距离必须不同。
- [ ] **B3 真正的 walk-forward**：每折在训练集上**独立重新选参**，再用测试折评估；不得以固定策略重跑子窗口冒充。测试断言不同折可以选出不同参数。
- [ ] **B4 多重检验校正**：对 N 组参数取优后校正选择偏差（Deflated Sharpe / Reality Check / 按试验次数调整的置信下界）。JSON 含 `n_trials` 与校正后显著性字段；校正后不显著时必须输出"无统计显著优势"并反映在 `action` 上。
- [ ] **B5 共识而非单点，且策略族去相关**：输出为 Top-K 的**跨策略族共识**并给出分歧度。硬约束：最终候选集中任一策略族占比 **≤ 50%**（当前 StochRSI 占 7/12 = 58%，必须被打破）；JSON 含 `consensus` 与 `dispersion`。
- [ ] **B6 建议可复现（核心可靠性指标）**：对 600519 分别用 `full` / `drop_last_60` / `drop_last_120` 三个窗口运行，最终 `action` 与首选**策略族**在三个窗口下必须**完全一致**（当前实测 argmax 翻转、Top5 重合仅 1~2）。JSON 含 `stability` 字段量化该稳健性。
- [ ] **B7 bootstrap 置信区间**：年化、最大回撤、胜率、相对买入持有的超额收益均给出 95% CI 而非点估计。JSON 含 `ci_95`；测试断言区间宽度随交易数减少而增大。
- [ ] **B8 基线显著性**：`no_edge` 判定不得只比较年化点值，须基于超额收益的 bootstrap/配对检验置信区间。测试：与买入持有等价的策略必须判为 `no_edge`；显著优于基线的策略必须不判为 `no_edge`。
- [ ] **B9 建议必须给出失效条件**：输出含 `invalidation`（何种价格/指标状态使本建议作废），供 Hermes 向用户解释与后续跟踪。

### C. 可消费性：Hermes 决策契约

- [ ] **C1 纯 JSON stdout**：`--json` 时 stdout 为单一 JSON 文档，人类可读文本走 stderr 或 `--text`，两者不得混流。校验：`python cli.py 600519 --json | python -c "import json,sys; json.load(sys.stdin)"` 成功。
- [ ] **C2 schema 自描述且入文档**：JSON 含 `schema_version`；README 提供完整字段表 + 真实示例 JSON + 调用示例 + 退出码表，使一个未见过本项目的 Agent 仅凭 README 即可正确调用与解析。
- [ ] **C3 建议可直接执行**：对 600519（股票）与 510300（基金）各运行一次，JSON 中以下字段全部存在且有值（数据不足时为显式 `null` + `reason`）：`action`(buy/sell/hold/avoid/insufficient_data)、`confidence`、`position_fraction`（**相对仓位比例，不含金额、不需要账户资金**）、`entry_zone`、`stop_loss`、`take_profit`、`horizon_days`、`distance_to_trigger`（当前值距触发价的百分比）、`invalidation`、`status`。
- [ ] **C4 消除自相矛盾**：属性测试——对任意构造数据，若卖出触发条件已成立，`action` 不得为 `buy`；若买入触发条件已成立，`action` 不得为 `sell`。以 600519 当前真实数据（StochRSI=100 的极度超买情形）作回归，输出必须与超买状态一致，且不得再出现"上穿 25（当前 100.00）"这类不可能的触发指引。
- [ ] **C5 状态与退出码可分支**：成功 / 数据不足 / 无优势(avoid) / 数据源失败 四种情形各有独立 `status` 与**互不相同**的非零/零退出码，且与 README 文档一致（逐一实测比对）。
- [ ] **C6 单一真源 API**：存在一个可导入函数返回该 schema，CLI 为其薄包装。测试断言 `advise("600519")` 返回 dict 的键集合与 `--json` 输出的键集合完全相同。
- [ ] **C7 基金同一契约**：`python cli.py 510300 --json` 通过同一 schema 校验，字段集合与股票侧一致。
- [ ] **C8 幂等确定性**：同一份缓存数据下连续运行两次，JSON 输出逐字节相同（固定随机种子；时间戳类字段须可关闭或从比对中排除并在文档说明）。

### D. 范围收敛与工程健康

- [ ] **D1 删除冗余**：移除自选股/watchlist 配置文件读写、`strategy_master` 批量优化与配置回写、`advisor/recommender.py::main` 的硬编码自选股、`fund_strategy/runner.py::main` 的 `save_config` 回写、`stock_config.example.json`、`fund_config.example.json`。`grep -r "watchlist\|save_config"` 无结果；仓库不含任何数据库、ORM、Web/前端依赖。
- [ ] **D2 测试离线全绿**：全部测试在无网络、无预置缓存 CSV 的环境下通过，0 failed / 0 error；用例总数 **≥ 25**（不低于现有）。当前因缺 `stock_600519_qfq.csv` 失败的那一项必须以合成 fixture 替代或加离线跳过保护。
- [ ] **D3 文档与代码一致**：README 的示例输出来自一次真实运行并标注运行日期与数据区间；不再出现网格中不存在的参数组合（如 `均线趋势(5-13-34)`）；不再宣称未经实现的机制（walk-forward 逐折寻优、基金 Wilson 评分、基金双边费率）；`requirements.txt` 固定版本 == 通过全部测试的实测环境版本；README 声明的 Python 版本与实际支持一致。
- [ ] **D4 输出数据驱动**：`cli.py` 中 45 个手写策略文案分支收敛为由策略元信息驱动的生成逻辑，`cli.py` 行数较当前 1689 行显著下降。验证：新增一个临时测试策略，**不修改任何 print 分支**即可同时获得正确的文本与 JSON 输出。
- [ ] **D5 性能有界且分档**：在实现全套统计严谨化后，单标的全量模式 **≤ 300s**（4 并行），并提供 `--fast` 档 **≤ 60s**；两档实测耗时写入 README。

## Boundaries

- **不新增数据库、不新增任何前端/Web UI/可视化界面、不新增账户持仓或自选股的持久化存储**（用户已明确排除）。
- **不引入需要 API key、登录或付费的数据源**；继续使用现有公开接口（东方财富/新浪/akshare）与本地 CSV 缓存，不改变缓存目录与 `.gitignore` 策略。
- **不引入重型依赖**（scikit-learn / statsmodels / torch / tensorflow / scipy 之外的编译型包）。统计功能优先用 numpy/pandas 自实现；确需新增依赖时限定为纯 Python 包，在 `requirements.txt` 固定版本，并在最终报告中说明理由。
- **不得为了让测试通过而放宽阈值、放宽门槛或把期望值硬编码/拟合到测试里**；任何阈值变更必须有量化依据并在报告中说明。
- **不删除现有测试用例**；仅可新增，或在断言本身错误时修正并说明理由。
- **不提交任何真实配置文件、账户信息、持仓数据或个人隐私**；示例数据一律用公开标的与合成数据。
- **不做确定性收益承诺**；所有输出必须保留"不构成投资建议"的免责声明，并如实表达不确定性（置信区间、显著性、分歧度）。当证据不足时必须输出"观望/无优势"而非强行给出方向性建议。
- **不扩大范围**：不实现自动下单、实盘对接、行情推送、多账户、风控中台等本次未列入验收标准的功能。
- 本次工作在当前仓库 `main` 分支的现有工作树内进行；工作树当前干净（HEAD `e183cb6`），不重写已有提交历史。
